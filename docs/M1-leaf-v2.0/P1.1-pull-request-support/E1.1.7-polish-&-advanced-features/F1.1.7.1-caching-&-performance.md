# F1.1.7.1: Caching and Performance

Add lightweight caching and request coalescing so pull request browsing feels responsive without becoming stale. Includes caching for reviewer-directory data.

## Deliverables
- List/detail cache strategy with short TTL.
- Reviewer-directory cache per repo for reviewer autocomplete (avoid re-fetching during create form sessions).
- Per-key request coalescing to avoid duplicate provider calls.
- Mutation-triggered invalidation rules.

## Implementation Notes
- Cache by repository, provider, and filter state.
- Keep list caches short-lived and invalidate them after create/update/merge/close actions.
- Cache reviewer-directory data briefly per repo. For GitHub, this may mean separate collaborator and repository-team caches behind one search surface. For Azure DevOps, this means short-lived identity results.
- Avoid a single global lock when a per-key guard will do.
- Keep cache behavior inside the PR service layer rather than scattering it across view-models.

## Acceptance Criteria
- [ ] Reopening the PR section or create form avoids unnecessary repeat API calls.
- [ ] Cache invalidation happens after PR mutations.
- [ ] Rapid selection changes do not trigger avoidable duplicate requests.
