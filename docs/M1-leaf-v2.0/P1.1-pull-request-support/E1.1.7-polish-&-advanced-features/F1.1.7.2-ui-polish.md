# F1.1.7.2: UI Polish

Tighten the PR tree section, main-area detail view, and create form UX so they feel like a native part of Leaf rather than an add-on.

## Deliverables
- Loading, empty, and error states for PR tree section, detail view, and create form.
- Better badges, status chips, and spacing for PR rows and detail headers.
- Smooth content-mode transitions (graph ↔ create form ↔ detail view) without visual artifacts.
- Keyboard and focus behavior that matches existing tree interaction patterns.

## Implementation Notes
- Keep the styling aligned with current `BranchListView`, `CommitDetailView`, and `DiffViewerControl` patterns.
- Favor compact tree rows over visually heavy cards.
- Preserve clear affordances for draft, merged, failed checks, provider links, and "Open in browser".
- Ensure actionable toast notifications built on the existing notification stack look polished for success/info states, not just errors.
- Polish the create form layout to match the look shown in the design reference (Azure DevOps-style branch dropdowns, clean field spacing).

## Acceptance Criteria
- [ ] PR rows are readable and compact in the existing tree width.
- [ ] Main-area detail and create views communicate loading and failure clearly.
- [ ] Content-mode transitions are smooth.
- [ ] Keyboard navigation remains coherent across tree, main-area views, and diff surfaces.
