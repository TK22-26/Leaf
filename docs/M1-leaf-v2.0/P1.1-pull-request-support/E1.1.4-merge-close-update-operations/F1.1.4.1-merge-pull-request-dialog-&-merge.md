# F1.1.4.1: Merge Pull Request Dialog and Merge

Add a merge flow that reflects provider capabilities and routes refresh through the current event architecture. The merge dialog is a modal confirmation (appropriate for destructive actions), launched from the main-area PR detail view.

## Deliverables
- Merge dialog for method selection and confirmation.
- Merge execution for supported provider methods.
- Merge result handling with clear user feedback.

## Implementation Notes
- Launch from the PR detail view in the main content area.
- The merge dialog remains a modal dialog (not inline) because merge is a destructive, confirmable action.
- Surface merge method capability differences such as Azure DevOps rebase limitations.
- Use current PR detail data plus provider refetches to confirm mergeability, checks, and review state.
- After success, invalidate PR caches and request repository refresh through `IRepositoryEventHub`.
- Users can always choose to merge via browser instead using the persistent "Open in browser" link.

## Acceptance Criteria
- [ ] Merge actions support provider-appropriate methods.
- [ ] Failed merges surface actionable explanations.
- [ ] Successful merges refresh tree state, detail state, and git history.
- [ ] The merge flow does not introduce custom refresh event plumbing.
