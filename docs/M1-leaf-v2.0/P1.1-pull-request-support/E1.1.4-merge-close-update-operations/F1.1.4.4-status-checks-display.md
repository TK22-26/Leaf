# F1.1.4.4: Status Checks Display

Show CI and policy state in the main-area PR detail view so merge readiness is visible before the user attempts a merge.

## Deliverables
- Check and policy summary in the PR detail view.
- Provider-neutral display model for success, pending, failure, error, and cancelled states.
- Actionable warnings for merge-preventing failures.

## Implementation Notes
- Prefer using pull request head SHA already present in summary/detail data when provider APIs need it.
- Keep provider-specific policy or pipeline terminology mapped into a neutral UI where practical.
- Show links back to provider detail pages when available (opens in browser).
- Do not block merge unconditionally in the UI unless the provider capability data is authoritative.

## Acceptance Criteria
- [ ] Checks and policy results display in the main-area PR detail view.
- [ ] Pending and failed states are distinguishable.
- [ ] Merge flow can consume the same status data without extra architectural churn.
