# F1.1.1.1: PR Data Models

Define provider-neutral pull request and reviewer models that work in the repository tree, the main-area detail view, and the inline create form.

## Deliverables
- `PullRequestInfo` with immutable provider data plus observable selection state.
- `PullRequestDetails` for expanded detail payloads.
- Supporting models for files, reviews, comments, checks, merge results, and query identities.
- `ReviewerInfo` model for provider-neutral reviewer directory data used in reviewer autocomplete search, including reviewer kind (`user`, `team`, or `group`), display name, secondary identifier, avatar URL when available, and the stable provider key/slug/id needed for assignment.
- Tree plumbing updates in `BranchCategory` and `RepositoryInfo` so PRs can be selected the same way tags and worktrees are selected today.

## Implementation Notes
- Keep provider-specific values out of public models unless there is no neutral shape.
- Add only the observable properties needed for UI state such as selection or loading state.
- Extend `BranchCategory` with `PullRequests` and `IsPullRequestsCategory` rather than creating a parallel tree type for this milestone.
- Add repository-level helpers to clear or switch PR selection without mixing branch, tag, worktree, and PR selection accidentally.
- `ReviewerInfo` must support GitHub users (login-based), GitHub teams (slug-based), and Azure DevOps users/groups (GUID-based) through a shared shape.

## Acceptance Criteria
- [ ] PR summary and detail models compile without provider references leaking into the UI.
- [ ] `ReviewerInfo` model supports reviewer kind plus the provider key/slug/id needed to assign both individual and aggregate reviewers.
- [ ] Tree items support selection and binding in `BranchListView`.
- [ ] Model names and fields support both GitHub and Azure DevOps mapping.
- [ ] Existing branch/tag/worktree model behavior is not regressed.
