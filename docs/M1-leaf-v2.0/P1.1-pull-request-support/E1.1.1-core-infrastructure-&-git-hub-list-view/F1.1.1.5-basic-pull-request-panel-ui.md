# F1.1.1.5: Pull Requests Tree Section UI

Legacy filename retained for continuity. The implementation direction is a tree section with add/filter controls, not a standalone panel.

## Deliverables
- Add a `PULL REQUESTS` category to the existing repository tree.
- PR section header includes:
  - Collapsible expander with open PR count badge.
  - "+" add button that switches the main content area to the PR create form.
  - Filter button that opens a popup with filter options (open/closed/merged, author, etc.).
- Default filter: show open PRs only.
- Add a PR item template showing number, title, author, draft state, and updated time.
- Preserve the existing look and interaction style used by branches, tags, and worktrees.

## Implementation Notes
- Reuse the current `BranchCategory` template path in `BranchListView`.
- Extend the current category-header template rather than pretending it already supports this layout. Today it has count text plus one category action slot; PRs need badge styling plus two header actions.
- Keep PR browsing compact; do not add a second left/right split browser inside the app.
- The "+" button triggers a command on `MainViewModel` that switches the main area to the create form (handled in F1.1.3.1).
- The filter button opens a small popup or flyout with checkboxes/options for PR state filtering.
- Keep item selection behavior aligned with tag and worktree single-select patterns unless multi-select becomes necessary later.

## Acceptance Criteria
- [ ] The tree shows a `PULL REQUESTS` section only for supported repositories.
- [ ] Section header has count badge, "+" button, and filter button.
- [ ] Default filter shows only open PRs; filter popup allows changing to closed/merged/all.
- [ ] PR items render clearly without crowding the current tree layout.
- [ ] Clicking a PR selects it and switches the main area to PR detail view.
- [ ] Clicking "+" switches the main area to the PR create form.
- [ ] Existing category rendering for branches, tags, and worktrees remains intact.
