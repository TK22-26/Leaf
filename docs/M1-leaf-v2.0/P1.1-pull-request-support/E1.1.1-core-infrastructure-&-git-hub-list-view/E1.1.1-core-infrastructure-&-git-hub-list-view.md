# E1.1.1: Core Infrastructure and GitHub Tree Integration

**Current State:** Leaf has no pull request support and the old planning docs assume a standalone PR panel with right-side detail.

**Target State:** GitHub pull requests load into a new `PULL REQUESTS` tree section with add/filter buttons, selection switches the main content area from git graph to PR detail view when repository state allows it, and the underlying service contracts support reviewer search across the reviewer types each provider can supply.

## Deliverables
- Provider-neutral PR models, reviewer models, and query/result types.
- `IPullRequestService` facade plus GitHub-backed implementation path, including separate user and team discovery for reviewer search.
- Tree integration through `BranchCategory`, `BranchCategoryItemsConverter`, and `BranchListView` with add button, filter button, and count badge.
- `MainViewModel` multi-mode content area switching and detail-surface plumbing.

## Acceptance Criteria
- [ ] GitHub PRs are discoverable from the repository tree with count badge.
- [ ] PR section header has "+" (add) and filter buttons.
- [ ] No standalone `PullRequestPanel` is introduced.
- [ ] Service contracts align with current session and refresh patterns, including reviewer search for users/teams/groups as supported by each provider.
- [ ] Selecting a PR switches the main content area from git graph to PR detail view and hides the right-side repository panel when repository state allows it.
- [ ] If merge/conflict or orphaned-conflict state is active, PR entry is blocked with an actionable toast instead of hiding the resolution UI.
- [ ] Navigating back (close button, tree selection, or graph commit selection) restores the git graph and normal right-pane behavior.
- [ ] Existing branch, tag, and worktree interactions still behave correctly.
