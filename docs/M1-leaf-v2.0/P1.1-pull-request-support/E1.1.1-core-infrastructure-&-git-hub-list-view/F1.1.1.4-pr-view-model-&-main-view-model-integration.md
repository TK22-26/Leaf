# F1.1.1.4: PR ViewModel and MainViewModel Integration

Integrate pull request selection and the multi-mode main content area into existing view-model flows.

## Deliverables
- `MainViewModel` content-mode state management: git graph (default), PR create form, or PR detail view.
- `MainViewModel` pull request state and commands.
- `PullRequestDetailViewModel` for selected PR detail loading and actions.
- `BranchListView.xaml.cs` click and context-menu handling for PR items.
- `MainWindow.xaml` visibility and content switching for the three main-area modes. Right-side repository panel hides when in PR mode.

## Implementation Notes
- Add a content-mode enum or equivalent state to `MainViewModel` that drives which view is visible in the main area (git graph, create form, or detail view).
- Selecting a PR in the tree sets the mode to detail and hides the right-side repository panel when repository state allows it. Clicking close/back, selecting a branch/tag/worktree in the tree, or selecting a commit in the graph restores the graph and normal right-pane behavior.
- Attempting to enter PR detail or create mode while merge/conflict or orphaned-conflict state is active should show an actionable toast and keep the current repository-state UI visible.
- Mirror the interaction model already used for branches, tags, and worktrees for tree selection behavior.
- Add PR-specific selection helpers instead of overloading branch multi-select collections.
- Route post-mutation refresh through `IRepositoryEventHub`.
- Keep async work out of event hub handlers; schedule async refresh from synchronous entry points as the current architecture expects.
- Follow current constructor injection and composition-root patterns in `MainWindow.xaml.cs`.

## Acceptance Criteria
- [ ] Selecting a PR from the tree switches the main area to PR detail view and hides the right-side repository panel when repository state allows it.
- [ ] Attempting to enter PR mode during merge/conflict or orphaned-conflict state leaves the current resolution UI visible and shows an actionable toast.
- [ ] Deselecting or switching back to commit history restores the git graph and normal right-pane behavior.
- [ ] Content-mode transitions are clean with no stale state from previous modes.
- [ ] PR commands are available only when the selected repository supports them.
- [ ] No custom `GraphRefreshRequested` event chain is introduced.
