# F1.1.1.3: GitHub PR Service Implementation

Implement the GitHub provider adapter for list, basic detail, and reviewer search flows using current PAT-based auth and realistic git integration points.

## Deliverables
- GitHub list and detail endpoints with pagination.
- Mapping from GitHub payloads into provider-neutral PR models.
- Capability support for create, update, merge, close, checks, comments, reviews, and commit lookup.
- Collaborator list endpoint (`GET /repos/{owner}/{repo}/collaborators`) for GitHub user reviewer autocomplete, with client-side filtering.
- Repository teams endpoint (`GET /repos/{owner}/{repo}/teams`) for GitHub team reviewer autocomplete, with client-side filtering by team name and slug.
- Request reviewers endpoint (`POST /repos/{owner}/{repo}/pulls/{pull_number}/requested_reviewers`) for both individual users and teams.
- Checkout support built from current `IGitService` primitives.

## Implementation Notes
- Reuse `CredentialService` owner-based PAT lookup.
- Use GitHub REST API pagination and capability-specific media headers where needed.
- Treat draft, merged state, checks, comments, and reviews as adapter responsibilities.
- Build checkout using `GetWorkingChangesAsync`, `GetBranchesAsync`, `FetchAsync`, `CheckoutAsync`, `SetUpstreamAsync`, and `PullBranchFastForwardAsync` instead of invented helper methods.
- Do not add or depend on GitHub OAuth device flow.
- For collaborator list: fetch all collaborators with pagination (100 per page), cache briefly per repo, and filter by login and display name. Requires `repo` + `read:org` PAT scopes.
- For repository teams: fetch available repository teams with pagination, cache briefly per repo, and filter by team name and slug. If the repo does not expose team access, return no team results without breaking user reviewer search.
- Team reviewers use the `team_reviewers` array in the same request-reviewers endpoint, identified by team slug.

## Acceptance Criteria
- [ ] Open, closed, and merged PRs list correctly.
- [ ] PR summaries map title, number, author, draft, and updated time correctly.
- [ ] Basic detail data can populate the PR detail view.
- [ ] User and team reviewer discovery return `ReviewerInfo` models suitable for autocomplete.
- [ ] Reviewer request correctly assigns individual users and teams.
- [ ] Checkout logic handles same-repo and fork cases with current git APIs.
- [ ] Provider errors surface clear PAT or permission failures (including scope-related 403 for collaborator or repository-team lookup).
