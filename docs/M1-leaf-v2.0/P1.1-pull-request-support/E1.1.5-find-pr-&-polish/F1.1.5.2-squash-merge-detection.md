# F1.1.5.2: Squash-merge Detection

Add heuristic fallback for commits that do not have a direct provider-side PR association, especially after squash merges.

## Deliverables
- Provider-specific heuristic lookup path.
- Heuristic result labeling so users can tell inferred matches from exact matches.
- Fallback integration with the commit-to-PR flow.

## Implementation Notes
- Prefer exact provider APIs first.
- Use commit message patterns, merge metadata, or provider search only as fallback.
- Keep heuristic matching conservative to avoid false positives.
- If confidence is low, show results as suggestions rather than a definitive match.

## Acceptance Criteria
- [ ] Exact match logic remains the primary path.
- [ ] Heuristic matches are labeled clearly.
- [ ] Squash-merged PRs become discoverable in common cases.
