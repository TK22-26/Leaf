# F1.1.2.2: File Diff Integration

Route PR file selection through the existing diff viewer so PR review uses the same diff surface already used elsewhere in Leaf.

## Deliverables
- Pull request file selection commands in `PullRequestDetailViewModel`.
- A provider-neutral method to load diffable content for a PR file.
- Diff viewer integration that can handle patch-backed and content-fetched diffs.

## Implementation Notes
- Prefer one pull request diff loading path that yields the same shape the current diff viewer already consumes.
- Use GitHub patch data when it is complete and trustworthy; fall back to fetching base/head file contents when patch data is absent or truncated.
- Design the service shape so Azure DevOps can plug in iterations-based file diffs later without reworking the UI.
- Respect binary and too-large-file cases with clear messaging instead of forcing a broken diff load.
- The diff viewer overlays the main content area the same way it does today when viewing commit diffs.

## Acceptance Criteria
- [ ] Clicking a changed file in PR details opens the existing diff viewer.
- [ ] Added, modified, deleted, renamed, and binary-file cases are handled explicitly.
- [ ] Missing patch payloads do not break the UI.
- [ ] The diff viewer can return to PR details cleanly.
