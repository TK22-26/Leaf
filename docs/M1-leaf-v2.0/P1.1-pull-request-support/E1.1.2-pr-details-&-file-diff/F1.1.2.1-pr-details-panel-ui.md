# F1.1.2.1: PR Detail View UI

Legacy filename retained for continuity. The goal is a PR detail view in the main content area (replacing the git graph), not a right-side panel.

## Deliverables
- `PullRequestDetailView` layout for summary, branches, body, files, commits, reviews, comments, checks, and actions.
- Close/back button that returns to the git graph and restores normal right-pane behavior.
- Persistent "Open in browser" link in the detail header — always visible, never buried in a menu.
- `MainWindow.xaml` updates so the main content area switches between git graph and PR detail view based on `MainViewModel` content-mode state.
- Right-side repository panel hidden while PR detail is active.
- Empty, loading, and error states appropriate for tree-driven selection.

## Implementation Notes
- The PR detail view occupies the full main content area where the git graph normally renders. It is not a right-side panel or sidebar.
- Surface source and target branches, provider link, draft/merged status, and merge availability near the top.
- Include a close/back button (top-left or toolbar area) to return to the graph. Selecting a branch/tag/worktree in the tree or a commit in the graph also returns to the graph.
- Do not enter PR detail mode while merge/conflict or orphaned-conflict state is active. Show an actionable toast and keep the repository-state UI visible instead.
- Keep file list and comments virtualized or lazy-loaded where needed.
- The "Open in browser" link should open the PR's web page in the user's default browser.

## Acceptance Criteria
- [ ] Selecting a PR replaces the git graph with PR detail content in the main area.
- [ ] Right-side repository panel is hidden while PR detail is active.
- [ ] Close/back button restores the git graph and normal right-pane behavior.
- [ ] Attempting to open PR detail during merge/conflict or orphaned-conflict state shows an actionable toast and leaves the current resolution UI in place.
- [ ] "Open in browser" link is always visible in the detail header.
- [ ] Unselected PR state shows an appropriate empty message or returns to graph.
- [ ] Detail layout works well at various window sizes.
- [ ] PR actions are placed where they can later support merge, close, and update flows cleanly.
