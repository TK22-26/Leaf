# E1.1.2: PR Details and File Diff

**Current State:** After E1.1.1, pull requests are visible in the tree and selectable, and the main content area can switch modes, but the detail experience is still minimal.

**Target State:** Selecting a PR opens a full pull request detail view in the main content area (replacing the git graph) when repository state allows it, with file diff, commits, reviews, comments, markdown fallback rendering, a close/back button, and a persistent "Open in browser" link.

## Deliverables
- `PullRequestDetailView` rendered in the main content area with close/back navigation.
- Persistent "Open in browser" link in the detail header.
- File selection that routes through the existing diff viewer.
- Reviews, comments, checks, and commits surfaced lazily.
- Basic markdown fallback for PR body and comments.

## Acceptance Criteria
- [ ] Pull request details render in the main content area, replacing the git graph.
- [ ] Right-side repository panel is hidden while PR detail is active.
- [ ] If merge/conflict or orphaned-conflict state is active, PR detail mode is blocked with an actionable toast instead of hiding the resolution UI.
- [ ] A persistent "Open in browser" link is visible in the detail header.
- [ ] Close/back button returns to the git graph and restores normal right-pane behavior.
- [ ] File diffs reuse the existing diff viewer flow.
- [ ] Reviews, comments, commits, and checks can load independently.
- [ ] Large PRs remain usable through lazy loading and virtualization.
