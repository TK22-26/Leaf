# F1.1.3.2: Branch Context Menu Integration

Add `Create Pull Request...` to the existing branch context menu so PR creation can also start from the same place users already manage branches.

## Deliverables
- Branch context-menu command for local branches.
- Capability checks based on repository remote support.
- Preflight messaging for branches that need to be pushed or configured first.

## Implementation Notes
- Integrate in `BranchListView.xaml` next to existing branch actions rather than adding a new toolbar just for PRs.
- This is the secondary entry point; the primary entry point is the "+" button in the PR section header.
- Selecting `Create Pull Request...` from the context menu switches the main content area to the create form (same as clicking "+"), with the selected branch pre-populated as the source branch.
- If merge/conflict or orphaned-conflict state is active, do not enter create mode. Show an actionable toast and keep the current repository-state UI visible.
- Prefer enabling the action only when the current repository supports PRs.
- If the selected branch has no usable upstream, either disable with explanation or prompt the user into the required push/setup flow before creation.
- Keep command routing in `MainViewModel` so tree code-behind stays thin.

## Acceptance Criteria
- [ ] `Create Pull Request...` appears in the branch context menu for supported repositories.
- [ ] The selected branch becomes the default source branch in the create form.
- [ ] The main content area switches to the inline create form (not a dialog).
- [ ] Merge/conflict or orphaned-conflict state blocks entry into create mode with an actionable toast.
- [ ] Unsupported repos or unsuitable branches show a clear explanation.
- [ ] The integration matches current context-menu behavior and styling.
