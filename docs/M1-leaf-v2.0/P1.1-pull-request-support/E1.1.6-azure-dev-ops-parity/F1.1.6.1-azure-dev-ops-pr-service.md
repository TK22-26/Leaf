# F1.1.6.1: Azure DevOps PR Service

Implement the Azure DevOps provider adapter behind the same pull request service facade used by GitHub, including identity search for reviewer autocomplete.

## Deliverables
- Azure DevOps list/detail/create/update/merge/close support.
- Remote parsing for organization, project, and repository identity.
- Mapping into provider-neutral PR models.
- Identity search endpoint (`GET /_apis/identities?searchFilter=General&filterValue={term}`) for reviewer autocomplete with server-side filtering.
- Add reviewer endpoint (`PUT /pullRequests/{id}/reviewers/{reviewerId}`) for both individual users and groups.

## Implementation Notes
- Reuse PAT lookup through `CredentialService` organization keys.
- Keep provider-specific REST details inside the adapter.
- Parse Azure remote URLs carefully for both hosted and server variants where feasible.
- Align cancellation and refresh behavior with the GitHub path so the UI does not branch unnecessarily.
- For identity search: use the Identities API with `searchFilter=General` for combined name/email search. Filter by `isActive: true`. Distinguish users from groups via `isContainer` flag.
- Reviewer assignment uses the user's identity GUID (not email). Groups can be assigned as reviewers (aggregate member votes).
- Required PAT scopes: `vso.code_write` for PR operations, `vso.identity` for identity search.

## Acceptance Criteria
- [ ] Azure DevOps repositories can list and select PRs.
- [ ] Core mutation flows map cleanly into provider-neutral results.
- [ ] Identity search returns `ReviewerInfo` models suitable for autocomplete.
- [ ] Reviewer assignment correctly handles individual users and groups.
- [ ] Auth and permission failures surface clear PAT guidance (including scope requirements).
- [ ] The implementation plugs into the same tree and main-area detail UX as GitHub.
